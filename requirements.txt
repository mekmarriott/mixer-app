# Serving dependencies — what Vercel installs for the API function.
#
#   python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
#
# This is the SERVING subset. It deliberately excludes scipy, requests and
# essentia: none is reachable from the request path, because analysis,
# segmentation and time-stretch are ingest-time only and run locally
# (docs/infrastructure-plan.md §5.3). The modules holding them import them
# lazily, so nothing drags them back in.
#
# Measured: with scipy the dependency set is ~158 MB installed, against
# Vercel's 250 MB uncompressed function limit. Without it, ~53 MB. That
# headroom is the difference between deploying and not.
#
# Excluding essentia here has a second, non-size reason: it is AGPL-3.0, whose
# copyleft is triggered by *network* use. Keeping it off the network-facing
# server — it runs only during local ingestion — is what stops that clause
# firing at all. See docs/requirements.md §4.
#
# RUNNING THE APP LOCALLY OR THE TEST SUITE NEEDS MORE THAN THIS.
# Use requirements-ingest.txt, which includes this file.

Flask==3.1.0
numpy==2.2.1

# Postgres driver for the Supabase deployment target. Unlike local development
# — which runs on stdlib sqlite3 and needs neither of these — the deployed
# function always talks to Postgres, so both belong in the serving manifest.
# engine.py uses psycopg_pool.ConnectionPool, so psycopg alone is not enough.
psycopg[binary]==3.2.3
psycopg-pool==3.2.4
